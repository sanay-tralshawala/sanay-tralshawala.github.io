Agentic Bus Routing from Disruption Data

Jan – May 2025 · Carnegie Mellon University · AI Agents · NLP

Overview

Transit disruptions — road closures, accidents, severe weather — are a daily reality for public bus networks. The challenge is that disruption information arrives as unstructured text (news articles, operator reports), and the gap between reading that text and producing an updated bus route is currently filled by manual dispatcher judgment under time pressure.

This project proposes an agentic backend pipeline that closes that gap automatically. A raw news article goes in; structured alternative route assignments come out. The system was designed for Pittsburgh Regional Transit (PRT) and tested on single-road and multi-road disruption scenarios across the city's street grid.

My Contributions

This was a four-person team project. My core ownership was the News Parser Agent, the confidence scoring system, and the end-to-end orchestration pipeline.

News Parser Agent

The News Parser Agent is a LangChain-based agent responsible for converting raw text into structured disruption data. I designed it as a two-stage pipeline to reduce cognitive load on each sub-agent:

Stage 1 — Disruption Event Classification: The first sub-agent determines whether the input text describes a road disruption at all. It outputs a JSON object with a classification (true/false), a detailed explanation, and a confidence score. If the article is irrelevant — a sports update, a weather forecast with no traffic impact — the pipeline exits here, logging the result without triggering any routing actions.

Stage 2 — Disruption Event Description: If Stage 1 classifies a disruption, the full article and Stage 1's explanation are passed to a second sub-agent. This agent extracts structured fields: affected roads, intersections, neighborhoods, area description, severity, estimated duration, and a source quote. It is explicitly instructed to use only information present in the article and to be specific to Pittsburgh geography, preventing hallucinated locations.

Confidence Scoring

Both sub-agents produce a confidence score (0.0–1.0) as part of their structured output, representing the model's self-assessed certainty that the extraction is accurate and actionable. I designed a threshold-based filtering mechanism: articles below a minimum confidence are flagged for operator review rather than being auto-routed.

This adds a human-in-the-loop layer that matters in practice — a vague report ("some traffic issues in the East End") should not trigger automatic rerouting on its own. In testing, the system correctly assigned low confidence (0.40) to vague bulletins, near-zero confidence (0.02) to irrelevant articles, and high confidence (0.88–0.95) to specific road closure reports with named intersections.

Orchestration Pipeline

I designed and wrote the overall six-stage orchestration that connects all components: (1) parse the input article, (2) extract structured disruption fields, (3) build disruption corridors from extracted addresses, (4) identify affected PRT routes via the Google Maps and Geocoding APIs, (5) substitute disrupted stops with nearest available alternatives on unaffected routes, and (6) compile a structured summary.

The pipeline supports two entry paths — a live operator-provided article or a synthetic news article generated by the team's MCP-based news generation tool. Both paths converge into the same sequential pipeline. A key design goal was graceful failure: each stage is independently debuggable, and low-confidence inputs exit early without corrupting downstream state.

Results

The pipeline was evaluated on four scenario types. For an irrelevant article (Steelers roster news), the parser correctly assigned confidence 0.02 and suppressed routing. For a vague bulletin (generic East End traffic alert), it returned confidence 0.40 with no specific roads — appropriate for operator review. For a single-road closure (Forbes Avenue, Squirrel Hill), the system produced a confident extraction (0.95) and generated a correct neighborhood-scale detour. For a multi-road corridor disruption (Liberty Avenue through the Strip District), it correctly identified a corridor-scale event (0.88) and generated a geographically distinct northward bypass.

Key Takeaways

Decomposing the parsing task into classification then extraction — rather than asking one agent to do both — significantly improved reliability. The confidence mechanism proved its value: a single agent asked to both classify and extract tends to commit to extractions it isn't sure about, whereas separating the stages surfaces uncertainty earlier. The hardest remaining challenge is spatially vague inputs; the system struggles when location is implied rather than stated, which points toward future work in map-grounded retrieval or richer geographic reasoning.
